# 3D动捕工作台

基于本机已经安装的 XR Animator 0.35.0，保留人物渲染与原功能实现，新增简体中文控制台。这是一份独立副本。

## 启动

双击桌面 **3D动捕工作台**，或本目录的 **启动3D动捕工作台.cmd**。

目前使用本机原安装目录里的 Electron 运行时：`C:\Users\14984\AppData\Local\Programs\XR Animator\XR-Animator_electron-v37.3.0-win32-x64_SA\electron.exe`。人物引擎源码、界面源码和配置在此目录。原版必须保留；这个版本还不是可以复制到另一台电脑的完整安装包。

## 已接通的功能

“人物与模型”页面内置三个本地人物：默认少女（日系动漫）、罗伯特（卡通低多边形）、小方机器人（科幻）。点击缩略图切换，当前人物有明确标记。新增两个人物来自 Polygonal Mind 的 100Avatars R1，作者目录和 VRM 内嵌授权均为 CC0；来源、SHA-256 和授权文本保存在 `models/`。默认少女沿用原包授权。人物切换复用引擎模型缓存，七次连续切换、恢复默认及口型参数验证见 `models-test-result.json`，实际界面见 `models-preview.png`。本次模型测试没有启用摄像头或动作追踪。

人物列表现已增加第四个“日常青年”（Kyle），自然肤色、T 恤长裤，仍为低多边形卡通风格。其内嵌授权为 CC0，支持手指骨骼、眨眼和五种口型。最新 `models-test-result.json` 验证四个人物的九次连续切换和四套口型参数，测试没有开启采集。

第四个选项现替换为“写实男性”，来自微软 Rocketbox 的 Male_Adult_01，使用 MIT 授权。模型已转换为 VRM 1.0，保留全部面部形态键，映射口型、眨眼和情绪表情，并使用皮肤/衣物颜色与法线贴图。源码修复了无弹簧骨骼组件的加载，以及 VRM 1.0 标准化骨骼的姿态标定，使身体能正确站立、脚不被裁切。实际渲染检查见 `model-render-check.json`；授权、来源与转换说明在 `models/ATTRIBUTION.txt` 和 `Rocketbox-LICENSE.txt`。旧 Kyle 文件不再出现在人物选择中。

“打开原版高级窗口”是开关：首次点击显示原版窗口，按钮变为“关闭原版高级窗口”，再次点击收起原版窗口。切换左侧功能页也会收起。收起后人物引擎继续渲染，不退出 Studio。

动作菜单的“结束”已改为“关闭动作列表”。关闭后提供“重新打开动作列表”，人物仍保持当前动作；其他设置菜单关闭后也提供重新打开入口。点击当前左侧导航同样可以重新打开。

动作与姿态现已改为完整动作库，移除原菜单的“下一页动作”。可直接搜索全部 33 个可用动作，按站立、坐姿、行走、卧姿筛选，或点击“定位当前动作”。搜索和筛选固定在列表上方，只有动作区域滚动；姿态调整与自定义动作单独折叠。切换动作保留查询、筛选和滚动位置，收起后可重新打开。动作名称改为中文，并保留全身、上半身与足部区别。直接按稳定动作 ID 调用原生动作接口，动作列表随当前追踪模式调整。验证见 `pose-library-test-result.json`。

“场景与设置 → 视觉效果”现在在右侧显示真实表单：灯光颜色与位置、镜头视野、泛光、环境光遮蔽、景深及其 VRM 参数。表单直接调用原引擎 lil-gui 控制器的读写接口，保留原回调和范围限制；原版控件不会显示在控制台预览里。选择“返回场景与设置”可返回菜单。镜头参数是渲染视角，不会打开物理摄像头。

视频输入与动捕入口默认锁定，启动只加载人物。此次验证没有开启摄像头或身体追踪；这些功能的端到端采集验证留待后续。

左侧视频输入与动作捕捉旁现有独立开关。视频输入的“关闭”释放电脑端视频流并停止追踪；动作捕捉的“停止”仅停止追踪，保留视频流。关闭后“开启”打开来源或模式选择菜单。手机 DroidCam 应用可以继续运行。已实际验证停止追踪、视频轨道释放、重新打开与恢复采集，结果见 `capture-controls-result.json`。

## 纯色背景与视频输出

“场景与设置”顶部新增“纯色背景”，支持取色器、六位十六进制颜色代码，以及绿幕、蓝幕、白色、黑色、深蓝预设。应用后立即生效并保存到 `user-data/studio-settings.json`，重启仍保留；关闭开关恢复场景背景。

左侧新增“视频输出”，可开启或停止独立虚拟相机 **Avatar Camera**，支持 1280×720 与 1920×1080、目标 30 帧/秒。OBS 添加“视频采集设备”，设备选择 Avatar Camera，将分辨率设为自定义并与工作台一致。绿幕可添加 OBS“色度键”滤镜去除。输出不包含工作台导航、按钮和操作记录。最小化及暂停预览不影响输出；软件关闭时释放输出进程。输出默认关闭，需手动开启；分辨率在停止后修改。

虚拟相机采用 [Unity Capture](https://github.com/schellingb/UnityCapture) 的 MIT DirectShow 组件和 [pyvirtualcam](https://github.com/letmaik/pyvirtualcam)。仅注册到当前 Windows 用户，名称与 DroidCam 输入分开，不依赖 OBS 自己的虚拟相机。运行依赖安装在 `runtime/virtual-camera/python`，使用本机 Python 3.11。设备停止时接收端可能显示驱动的待机提示。测试通过真实 DirectShow 接收端验证 720p、1080p、纯色背景、暂停预览和最小化、停止重开，并检查八种页面/窗口组合。结果见 `output-test-result.json` 与 `output-pixel-check.json`；本机未安装 OBS，未验证 OBS 界面中的实际添加操作。

## 更适合操作者和 AI

人物预览支持原生视角操作：左键拖动旋转、右键拖动平移、滚轮向上拉近和向下拉远，工具栏“视角复位”恢复默认镜头。方向键旋转，Shift+方向键平移，+/- 缩放，Home 复位。输入直接传到原引擎相机控制器，预览与虚拟相机输出共享同一视角；预览缩放和留白区域的坐标映射已处理。拖动结束、失焦及取消时会释放鼠标状态。操作不启用摄像头或追踪。结果见 `viewport-test-result.json`。

Studio 0.2 改为浅色控制区与深色人物舞台，顶部状态条更紧凑。动作列表支持中文搜索、当前动作标记和高级选项折叠；新增暂停/恢复预览和缩放复位。预览暂停只停止控制台画面更新，不改变人物引擎或摄像头状态。操作记录可折叠；支持小窗口布局、可见键盘焦点和减少动画偏好。

设计依据和视觉规范见 `DESIGN.md`，本次应用了 ui-ux-pro-max 和 frontend-design。新增样式在 `app/studio-v2.css`；上一版界面保留为 `app/studio.v01.html`、`app/studio.v01.css`、`app/studio-renderer.v01.js`。

左侧导航单击切换，右侧设置单击执行，正常窗口不置顶、不穿透鼠标。所有按钮有文字名称；设置控件有稳定 ID、`aria-label` 和 `data-engine-key`，状态可直接读取 DOM。支持 Tab / Enter。

原引擎中的数字气泡菜单转成了真实 DOM 按钮，不依赖模拟键盘。高级设置仍沿用原引擎的菜单结构，尚未全部重写成独立表单。

控制台预览订阅本地引擎的渲染帧，目标约 30 帧/秒；画面右下角显示当前帧率。接收端解码后确认，避免帧队列积压；最小化或暂停预览时停止传输。以 JPEG 82 质量传输，人物舞台背景为深蓝色，原版高级窗口仍恢复透明背景。这是控制台预览，原引擎输出方式仍保留。

本机 10 秒对比测试中，旧截图/PNG 路径为 5.28 帧/秒，帧订阅/JPEG 路径为 26.60 帧/秒。每帧编码平均耗时由 25.02ms 降到 2.47ms。测试结果见 `performance-result.json`，帧率会随模型、窗口和本机负载变化。摄像头和追踪在测试中均关闭。

实现参考 Electron 官方的 [帧订阅接口](https://www.electronjs.org/docs/latest/api/web-contents/#contentsbeginframesubscriptiononlydirty-callback) 与 [NativeImage](https://www.electronjs.org/docs/latest/api/native-image)。

## 源码

- `app/studio.html`、`studio.css`、`studio-polish.css`：布局和样式。
- `app/studio-renderer.js`：导航、可访问控件、反馈和状态显示。
- `app/studio-preload.js`：隔离的控制台 IPC 接口。
- `app/studio-main.js`：控制台窗口、命令白名单与预览同步。
- `app/engine-bridge.js`：将原引擎菜单和动作适配成明确的命令。
- `engine/AT_SystemAnimator_v110350.gadget`：原引擎副本，其中 `js/electron_main.js` 和 `SystemAnimator_webkit.html` 加入了控制台加载入口。
- `user-data`：独立配置目录。
- `launch-context/SystemAnimator_path.txt`：运行时载入本副本的路径。

界面渲染进程禁用 Node 集成并启用上下文隔离，使用命令白名单调用引擎。旧引擎仍保留它原本需要的 Node 集成，尚未做完整安全重构。

## 验证

`test-result.json` 记录本机集成验证；`studio-preview.png` 是真实运行截图。

验证包括人物初始化、动作菜单和场景设置菜单、动作实际切换、按钮文字标签、预览帧加载，以及启动后的采集关闭状态。未验证全部高级菜单、任意第三方模型或摄像头采集效果。

0.2 另验证了动作搜索与无结果提示、当前动作标记、预览暂停/恢复、缩放复位、375/768/1040/1380 CSS 像素宽度无横向溢出及减少动画偏好。布局检查用 Electron 内置开发协议模拟视口；运行窗口仍以桌面尺寸为主。主要文字与背景对比度为 4.92:1 至 14.28:1。初始化状态现在等待原引擎真正开始运行。

布局修复：右侧设置卡片不再被 Flex 压缩并裁切，整列支持明确的垂直滚动条；高级设置与操作记录展开后可继续滚动。工具栏、模型信息和页头支持换行，长标签与文件名支持断行。菜单状态更新会保留高级设置展开状态和控件焦点。

`app/layout-audit.js` 用 `--studio-layout-test` 启动：遍历七个一级页面、六种窗口尺寸，展开高级选项及日志，加入超长名称，对每个可见控件逐一滚动并检查边界。结果写入 `layout-result.json`，列表底部截图为 `layout-bottom-preview.png`。测试只查看采集入口，不启用任何设备。
